# Lucky Games

## О проекте

Клиентское приложение для слот-игр. Пользователь открывает обычную веб-страницу на React, выбирает слот-игру и переходит к ней.

## Архитектура

- **Маршрутизация** — React Router DOM для перехода между оболочкой приложения и слот-играми.
- **Оболочка приложения** — React-страница для выбора игры и перехода к ней.
- **Слот-игры** — отдельные 2D-игры на PixiJS 8, интегрированные в React.
- **Состояние** — MobX для управления состоянием приложения и игр.
- **Анимация** — GSAP.
- **Аудио** — PixiSound.

## Структура проекта

```text
src/
├─ react/                  # React-клиент приложения
│  ├─ app/
│  │  ├─ hooks/            # состояние темы и синхронизация документа
│  │  └─ i18n/
│  │     └─ locales/       # переводы по языкам
│  ├─ pages/
│  │  ├─ catalog/
│  │  │  ├─ components/    # блоки каталога и карточки игр
│  │  │  ├─ hooks/         # состояние и действия каталога
│  │  │  ├─ layout/        # фон, шапка и подвал каталога
│  │  │  └─ model/         # данные и типы каталога
│  │  └─ egypt-slot/       # React-страница и canvas слота
│  ├─ shared/ui/icons/     # общие SVG-иконки
│  ├─ styles/              # глобальные стили и тема
│  └─ main.tsx             # точка входа React
├─ games/
│  ├─ shared/              # общий код игр: pixi/ и network/
│  └─ egypt-slot/
│     └─ src/
│        ├─ assets/        # URL и загрузка ресурсов египетского слота
│        ├─ controllers/   # управление PixiJS-приложением и игровыми сущностями
│        ├─ network/       # HTTP-сессия, WebSocket-команды и восстановление раунда
│        ├─ phases-flow/   # фазы и менеджер переходов между ними
│        ├─ runtime/       # контекст одной запущенной игры
│        ├─ scene/         # PixiJS-сцены египетского слота
│        └─ stores/        # состояние панели, барабанов и раунда
├─ assets/                 # общие статические ресурсы
└─ test/                   # настройка тестового окружения
```

Весь React-код находится в `src/react`: `app` отвечает за маршруты и глобальные настройки, `pages/catalog` — за каталог и его оформление, `pages/egypt-slot` — за React-страницу слота, а `shared/ui/icons` содержит общие иконки. Игровая логика, сети, состояние и PixiJS-сцены изолированы в `src/games`.

Для египетского слота создан модуль `src/games/egypt-slot/src/assets`. Остальные игровые слои и второй слот будут добавлены по мере уточнения требований.

`SlotStore` объединяет три MobX-стора: `PanelStore` хранит настройки ставки и серверный баланс, `ReelsStore` — последние символы барабанов и выигрышные линии, `RoundStore` — сессию, Free Spins и состояние раунда. Ответы сервера применяются через `SlotStore`; PixiJS-сцена отвечает за их отображение.

Для локального запуска достаточно `pnpm install` и `pnpm dev`. Сервер хранит игровые сессии и результаты раундов в `apps/server/data/game.sqlite`; Docker и PostgreSQL не требуются. Файл базы создаётся при первом запуске и исключён из Git.

Нажатие на карточку «Золотой храм» открывает `/games/egypt-slot`. React отображает на этом маршруте только полноэкранный canvas. `EgyptSlotFlow` запускает фазы init → loading → idle → spinning → result → idle. В фазе loading клиент восстанавливает или создаёт HTTP-сессию, загружает ассеты и применяет состояние сервера к MobX-стору до показа сцены. Фаза idle ожидает нажатие Spin. Фаза spinning запускает визуальное вращение и отправляет SPIN либо FREE_SPIN через WebSocket; серверный результат определяет конечные символы барабанов. Фаза result применяет баланс и бонусное состояние сервера, подсвечивает выигрышные позиции и возвращает игру в idle. При ошибке запроса барабаны возвращаются к предыдущим символам и выводится сообщение. Клиент не рассчитывает выигрыш самостоятельно. При уходе со страницы сетевое соединение, анимации, обработчики и PixiJS-приложение освобождаются.

Сетевой модуль находится в `src/games/egypt-slot/src/network`, общий контракт — в [`packages/contracts/README.md`](packages/contracts/README.md). ID сессии и незавершённая команда сохраняются в `sessionStorage` этой вкладки. После потери ответа клиент ищет раунд по HTTP, а при следующем Spin повторяет команду с тем же `requestId`, чтобы не списать ставку дважды. Команда `pnpm dev` запускает Vite и сервер с автоматическим перезапуском при изменении серверного кода. Vite проксирует `/api/slot` и WebSocket на `127.0.0.1:3001`. Для API на другом хосте задайте `VITE_SLOT_API_ORIGIN` в корневом `.env` (только origin, например `https://api.example.com`).

## Технологический стек

| Область               | Технологии                                |
| --------------------- | ----------------------------------------- |
| Клиентское приложение | React, TypeScript, Tailwind CSS           |
| Маршрутизация         | React Router DOM                          |
| 2D-графика игр        | PixiJS 8, @pixi/react                     |
| Анимация              | GSAP                                      |
| Аудио                 | PixiSound (`@pixi/sound`)                 |
| Управление состоянием | MobX, mobx-react-lite                     |
| Сборка и dev-сервер   | Vite                                      |
| Тестирование          | Vitest, React Testing Library, Playwright |
| Качество кода         | ESLint, Prettier                          |
| Пакетный менеджер     | pnpm                                      |
| Git workflow и хуки   | Git Flow, Husky                           |

URL игровых ресурсов описаны в `src/games/egypt-slot/src/assets`. Рабочий PSD и исходный PNG фона хранятся вне `public` в `design-assets/egypt-slot/`, поэтому не попадают в сборку. В `public` находится оптимизированный WebP. Для повторной конвертации фона запустите `pnpm assets:optimize`. Большой PSD при дальнейшей работе с Git лучше хранить через Git LFS.

## Проверки и тестирование

- **Vitest** — unit-тесты, интеграционные тесты и тесты React-компонентов.
- **React Testing Library** — рендеринг компонентов и проверки взаимодействия с интерфейсом.
- **Playwright** — браузерные и скриншотные тесты.

Полезные команды:

```sh
pnpm dev              # запустить приложение локально
pnpm build            # собрать production-версию
pnpm test             # запустить Vitest в watch-режиме
pnpm test:run         # запустить Vitest один раз
pnpm test:e2e         # запустить Playwright в Chromium
pnpm test:e2e:update  # обновить скриншотные baseline-файлы
pnpm lint             # проверить код ESLint
pnpm format:check     # проверить форматирование Prettier
```

Для установки браузера Playwright после установки зависимостей:

```sh
pnpm exec playwright install chromium
```

## Git workflow

Для работы с ветками используется Git Flow. Husky запускает проверки ESLint и Prettier перед коммитом.
