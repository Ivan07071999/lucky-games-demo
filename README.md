# Lucky Games

## О проекте

Клиентское приложение для слот-игр. Пользователь открывает обычную веб-страницу на React, выбирает слот-игру и переходит к ней.

## Архитектура

- **Маршрутизация** — React Router DOM для перехода между оболочкой приложения и слот-играми.
- **Оболочка приложения** — React-страница для выбора игры и перехода к ней.
- **Слот-игры** — отдельные 2D-игры на PixiJS 8, интегрированные в React.
- **Состояние** — MobX для управления состоянием приложения и игр.
- **Анимация** — PixiSpine и GSAP.
- **Аудио** — PixiSound.

## Структура проекта

```text
src/
├─ react/                  # React-клиент приложения
│  ├─ app/
│  │  ├─ components/       # компоненты оболочки
│  │  ├─ hooks/            # состояние темы и синхронизация документа
│  │  └─ i18n/
│  │     └─ locales/       # переводы по языкам
│  ├─ pages/
│  │  ├─ catalog/
│  │  │  ├─ components/    # блоки каталога и карточки игр
│  │  │  ├─ hooks/         # состояние и действия каталога
│  │  │  └─ model/         # данные и типы каталога
│  │  └─ game/             # React-обёртки страниц слот-игр
│  ├─ games/               # React-части конкретных игр по мере реализации
│  ├─ shared/ui/
│  │  ├─ icons/            # общие SVG-иконки
│  │  ├─ site-header/
│  │  └─ site-footer/
│  ├─ styles/              # глобальные стили и тема
│  └─ main.tsx             # точка входа React
├─ games/
│  ├─ shared/              # общий код игр: pixi/ и network/
│  └─ egypt-slot/
│     └─ src/
│        ├─ assets/        # URL и загрузка ресурсов египетского слота
│        ├─ controllers/   # управление PixiJS-приложением и игровыми сущностями
│        ├─ phases-flow/   # фазы и менеджер переходов между ними
│        ├─ runtime/       # контекст одной запущенной игры
│        └─ scene/         # PixiJS-сцены египетского слота
├─ assets/                 # общие статические ресурсы
└─ test/                   # настройка тестового окружения
```

Весь React-код находится в `src/react`: `app` отвечает за запуск и глобальные настройки, `pages` — за страницы, `games` — за React-обёртки конкретных игр, а `shared/ui` содержит общие компоненты интерфейса. Игровая логика, сети, состояние и PixiJS-сцены изолированы в `src/games`.

Для египетского слота создан модуль `src/games/egypt-slot/src/assets`. Остальные игровые слои и второй слот будут добавлены по мере уточнения требований.

Нажатие на карточку «Золотой храм» открывает `/games/egypt-slot`. React отображает на этом маршруте только полноэкранный canvas. `PhaseManager` запускает `init → loading → idle`; если загрузка не удалась, переход выполняется в `error`, откуда нажатие на кнопку или Enter повторно запускает `loading`. Менеджер проверяет допустимость переходов. Состояния загрузки и ошибки рисуются средствами PixiJS. `GameContext` создаёт общий `Controller` с доступом к `application` и `assets`. `AssetsController` объединяет каталог изображений, Spine-ресурсы и загрузчик. После загрузки фона `MainScene` получает его текстуру и масштабирует изображение под canvas. При уходе со страницы обработчики, сцены и PixiJS-приложение освобождаются. Загруженные изображения выгружаются из общего кеша PixiJS, когда их перестаёт использовать последний экземпляр игры; canvas удаляет React.

## Технологический стек

| Область               | Технологии                                          |
| --------------------- | --------------------------------------------------- |
| Клиентское приложение | React, TypeScript, Tailwind CSS                     |
| Маршрутизация         | React Router DOM                                    |
| 2D-графика игр        | PixiJS 8, @pixi/react                               |
| Анимация              | PixiSpine (`@esotericsoftware/spine-pixi-v8`), GSAP |
| Аудио                 | PixiSound (`@pixi/sound`)                           |
| Управление состоянием | MobX, mobx-react-lite                               |
| Сборка и dev-сервер   | Vite                                                |
| Тестирование          | Vitest, React Testing Library, Playwright           |
| Качество кода         | ESLint, Prettier                                    |
| Пакетный менеджер     | pnpm                                                |
| Git workflow и хуки   | Git Flow, Husky                                     |

Версию Spine runtime нужно согласовать с версией Spine Editor, из которой экспортированы игровые ассеты. Сейчас установлен `@esotericsoftware/spine-pixi-v8` 4.3.x, а `public/egypt-assets/Spine/character_anubis/character_anubis.json` экспортирован из Spine 3.8.99. Для использования Anubis в PixiJS 8 требуется повторный экспорт скелета и атласа из Spine Editor 4.3.x. До этого `EgyptSpineAssets.assertRuntimeCompatible()` сообщает о несовместимости.

URL игровых ресурсов описаны в `src/games/egypt-slot/src/assets`. Рабочий PSD и исходный PNG фона хранятся вне `public` в `design-assets/egypt-slot/`, поэтому не попадают в сборку. В `public` находится оптимизированный WebP. Для повторной конвертации фона запустите `pnpm assets:optimize`. Большой PSD при дальнейшей работе с Git лучше хранить через Git LFS.

## Проверки и тестирование

- **Vitest** — unit-тесты, интеграционные тесты и тесты React-компонентов.
- **React Testing Library** — рендеринг компонентов и проверки взаимодействия с интерфейсом.
- **Playwright** — браузерные и скриншотные тесты.

Полезные команды:

```sh
pnpm dev              # запустить приложение локально
pnpm build            # собрать production-версию
pnpm test             # запустить Vitest в watch-режиме
pnpm test:run         # запустить Vitest один раз
pnpm test:e2e         # запустить Playwright в Chromium
pnpm test:e2e:update  # обновить скриншотные baseline-файлы
pnpm lint             # проверить код ESLint
pnpm format:check     # проверить форматирование Prettier
```

Для установки браузера Playwright после установки зависимостей:

```sh
pnpm exec playwright install chromium
```
